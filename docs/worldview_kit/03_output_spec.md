# 输出文档说明 — 整理交付物的格式规范

> 这份文档由 Eric 在与你（claude.ai 端 Claude）讨论完世界观后上传。
> 看到它，意味着 Eric 认为讨论已经收敛，请你把这次对话里达成的所有共识整理成下面规定的格式。
> 整理过程中如果发现还有空白：先在文档里标注 `[待 Eric 决定]`，最后在《未决问题》清单里列出来。
> **不要为了凑齐字段而临场编造**——空着或标待定永远比胡编好。

---

## 你需要产出的 6 份内容

按顺序逐份输出，每份独立成段并以 `### 输出 N: <文件名>` 开头，便于 Eric 复制粘贴。

---

### 输出 1: `world.yaml`（全局世界观元数据）

```yaml
world_id: "<英文短 id，全小写下划线，例：vampire_court / postwar_town>"
display_name: "<中文世界名>"
era: "<时代，例：架空中古 / 1920s 民国 / 近未来 2087>"
location_macro: "<大地理位置，例：北方废墟城市 / 江湖小镇>"
genre: "<类型，例：都市悬疑 / 末世废土 / 古风武侠>"
tone: "<调性，从下列选：紧绷 / 温吞 / 阴郁 / 荒诞 / 怀旧 / 悬疑>"
language: "zh-CN"
notes: |
  <100–200 字导演阐述：这个世界让人有什么感觉，
  氛围关键词，Eric 想透过这个世界探讨什么>
```

---

### 输出 2: `layer_0_worldview.md`（给 prompt 用的纯文本世界观）

一段 **800–1500 字的中文**。这段会直接被复制进 `backend/src/llm/prompt_builder.py` 替换现有的 `LAYER_0_SYSTEM` 常量，所以**字数不达 800 字会让 DeepSeek 缓存命中率掉下 90%**——开发端会拒收。

结构（保留所有【】小标题，方便后端解析）：

```
你是一个生活在<世界名>的 NPC。本系统模拟一个由生成式智能体驱动的小型社会,
你将以你的角色身份,根据当前情境作出符合人物设定的反应。

【世界观:<世界名>】
<200–400 字:地理 / 时代 / 规模 / 整体风貌>

【时间与节奏】
<100–200 字:作息 / 季节 / 特殊日期 / 公共活动周期>

【社会结构与风俗】
<200–400 字:阶层 / 家族 / 人际规范 / 外来者待遇 / 禁忌>

【经济与生计】
<100–200 字:本地人靠什么吃饭 / 贫富分布 / 主要交易场所>

【当前氛围与潜在催化剂】
<100–200 字:写明"现在大家都在隐约感觉到的事"——
比如某种威胁、某个外来者、某场即将到来的活动>

【行为规则:你必须遵守的角色守则】
1. 你的所有回答必须基于你的人格设定与当前情境,不要打破角色,不要承认自己是 AI 或语言模型。
2. 所有输出必须使用简体中文,语言风格与你的职业、年龄、教育背景相符。
3. 当被要求做决策时,严格按要求的 JSON 格式返回,不要添加任何解释性文字、markdown 标记或前后缀。
4. 当回答日常对话时,长度以一到三句话为宜,不要长篇大论;除非用户明确要求详细解释。
5. 你的记忆有限,只记得「近期记忆」中提供的内容。如果被问到不在记忆中的事情,
   可以诚实表示「记不太清了」或「这事我不知道」,不要编造细节。
6. 你不知道未来会发生什么,只能基于当前情境与过往经历推断。
7. 如果被要求做超出你角色能力的事,应当礼貌拒绝并建议找合适的人选。

【输出风格】
- <2–4 条该世界特有的语言风格提示，例:可使用本世界特有口语词如「xxx」「yyy」>
- 避免现代书面语,除非你的角色就是那一类身份
```

**严格要求**：
- ❌ 不要写任何具体角色的名字（角色信息走 Layer 1，世界观保持通用）
- ❌ 不要写"接下来 3 天会发生什么"（那是模拟器跑出来的）
- ❌ 不要写超过 1500 字（Layer 0 不是越大越好，超过会浪费缓存空间）
- ✅ 必须 800 字起

---

### 输出 3: `locations.yaml`（场所清单）

3–4 个场所。`type` 必须从枚举里选。

```yaml
locations:
  - id: location_a
    name: "<中文名>"
    type: "social"  # 枚举: private / social / public / commercial / liminal
    description: |
      <100–200 字:场所外观 / 谁会来 / 什么时段最热闹 / 哪些人不属于这里>
    typical_occupants: ["agent_01", "agent_03"]
    open_hours: "07:00-22:00"
    adjacent_to: ["location_b"]

  - id: location_b
    name: "..."
    type: "..."
    description: |
      ...
    typical_occupants: [...]
    open_hours: "..."
    adjacent_to: [...]

  # 重复直到 3-4 个
```

**校验**：
- 至少 1 个 `social` 类型（核心交往场所）
- 至少 1 个 `liminal` 或 `private` 类型（"出事的地方"或"独处的地方"）
- `typical_occupants` 引用的 agent_id 必须在输出 4 中存在

---

### 输出 4: `personas/agent_01.yaml` ~ `agent_NN.yaml`（每个角色一份）

5–12 份。模板：

```yaml
id: agent_01
display_name: "<中文姓名,2-3 字>"
gender: "<男 / 女 / 其他>"
age: <整数>
occupation: "<职业>"
identity: "<一句话身份概括,例:镇邮局退休员工 / 黑帮老二的女儿>"
appearance: "<50-100 字外貌描写,便于美术参考>"

traits: ["<性格特质 1>", "<2>", "<3>"]
personality: |
  <100-300 字性格刻画:不要列形容词,
  写"她在 X 时会做 Y"这种行为级描述>

backstory: |
  <300-800 字背景故事:童年关键事件 / 转折点 / 目前处境 / 与本世界的渊源>

speaking_style: "<例:话少、爱用反问;爱讲粗口;说话带本地口音>"

long_term_goal: "<一句话:这辈子最想达成的事>"
mid_term_goal: "<一句话:这几个月在筹划的事>"
short_term_needs: "<一句话:今天/这周想做什么>"

initial_location: location_a
typical_locations: ["location_a", "location_b"]
daily_routine: |
  06:30 起床
  07:00 ...
  09:00 ...
  ...
  22:00 睡觉

initial_relationships:
  agent_02: "<例:是她哥哥,关系紧张但血浓于水>"
  agent_03: "<例:暗恋他但从未说出口>"
  # 不必写满,写有戏的就行

known_secrets: |
  <这个角色自己知道、但其他角色不知道的事,2-5 条,每条一行>

unknown_to_self: |
  <这个角色不知道、但玩家或其他角色知道的事,0-3 条;可空>

inner_conflict: "<一句话:他/她内心最大的矛盾>"

seed_memories:
  - importance: 8
    content: |
      <一段会被注入数据库的初始记忆,约 100 字,第一人称>
  - importance: 6
    content: |
      <第二条种子记忆>
  # 2-4 条
```

**全局校验（覆盖所有 agent）**：
- ✅ 至少 1 个 **外来者**（外乡人 / 新搬来的 / 视角与本地不同）
- ✅ 至少 **3 处明显张力**（在 `initial_relationships` 或 `known_secrets` 里能看出来）
- ✅ 至少 **2 处信息不对称**（A 的 `known_secrets` 涉及 B 但 B 不知道）
- ✅ 不能有两个角色 `occupation` 完全相同**且**互相无戏剧关系
- ✅ 所有 `display_name` 都是 2–3 个汉字（关键词检索友好）
- ✅ 所有 `initial_location` 引用的 location_id 必须存在于输出 3

**关于字段冗余**：当前后端代码（Block A/B/C）只消费 `id / name / age / occupation / personality / background` 这 6 个字段，其它字段是 **Block D / E / F / G 准备的前置存量**——请按完整 schema 输出，开发端 Claude 会逐步把它们接进代码。

---

### 输出 5: `catalyst.md`（潜在催化剂）

200–500 字。结构：

```markdown
# 潜在催化剂:<事件名>

## 是什么
<100-200 字描述这件可能发生的事>

## 触发条件
<什么样的 agent 行为/对话会让它真的发生>

## 已埋下的伏笔（在哪些 persona 的 known_secrets 里）
- agent_03: <一句话>
- agent_07: <一句话>

## 如果它发生了,每个角色大概会怎么反应
- agent_01: <一句话>
- agent_02: <一句话>
- ...
```

**注意**：催化剂不是"必然剧情"，是"有可能被触发的事"。模拟器是否真触发它取决于 agent 们怎么互动——这是涌现行为的源头。

---

### 输出 6: `pending_decisions.md`（未决清单）

任何在对话中没敲定、或者你不确定 Eric 真实意思的，全列在这里。模板：

```markdown
# 未决项

## 高优先级（影响开发推进）
- [ ] location_b 的具体名字（候选:A / B / C，Eric 待选）
- [ ] agent_05 是否真的与 agent_07 是兄弟关系（Eric 在两个版本之间犹豫）

## 中优先级（可后补）
- [ ] agent_03 的具体外貌（已有性格但没确定长相）
- [ ] 经济基础里"主要货币"是否需要明确（架空世界可能需要）

## 低优先级（味道层）
- [ ] 本地特色食物的名字
- [ ] 节日的具体名字
```

如果没有未决项，写一行 "无未决项" 即可。

---

## 输出顺序与格式

1 → 2 → 3 → 4 → 5 → 6，依次输出。

每份开头：`### 输出 N: <文件名>`
每份结尾：空一行再开始下一份。

YAML 部分用 ` ```yaml ` 代码块包裹；Markdown 部分用 ` ```markdown ` 代码块包裹。

---

## 不要做

- ❌ 不要总结"我们这次对话的过程"，只输出**结果**
- ❌ 不要在角色 backstory 里塞与世界观矛盾的设定
- ❌ 不要让两个角色的 long_term_goal 完全相同
- ❌ 不要把 `layer_0_worldview.md` 写成"故事大纲"——它是**设定文档**，不是剧情
- ❌ 不要为了凑字数硬凑——不够就标 `[待 Eric 决定]`
