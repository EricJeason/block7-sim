## 剩余 Block 详细规格

### Block G:每日反思 + Memory 压缩

**目标**:让长游戏(几十个游戏日)不爆 token + 提供可被 _plan_daily 消费的高层 reflection。

**两个独立子任务**:

#### G.1 每日反思(reflection.py 实现)
- 触发时机:每个游戏日结束时(由 Block H 的 sim loop 调度,或 scheduler 内部检测 game_time 跨日)
- 输入:当日所有 importance ≥ 4 的 memory(observation + plan)
- LLM:Pro + think_high(质量优先)
- 输出:5-10 条高层 reflection memory(如"今天三个治愈者都做了相似的梦,这不是巧合")
- 写入:memory_type='reflection',importance 由 LLM 给(自评分)
- prompt 模板放在 reflection.py,沿用 4 层结构(Layer 0 + Layer 1 + 当日 memory dump + reflection 任务)

#### G.2 旧 Memory 压缩(compression.py 完成)
- 触发时机:每个游戏日末尾(同 G.1)
- 规则(设计文档 §3.4):
  - 24 游戏小时内:全保留
  - 1-7 天前:importance ≥ 5 保留,importance < 5 合并为"日常摘要"(LLM 调用)
  - 7 天以前:仅保留 reflection 与 importance ≥ 7
- 实现细节:用 `MemoryStore.mark_compressed([ids])` 标记原始记忆;新摘要 memory 作为 reflection 类型新插入

**预计工作量**:~1.5 小时(LLMPlanner 已经为 prompt 构造打好基础,可复用 build_rich_layer_1)

**要测的**:
- mock 当日 50 条 memory → 验证 reflection 输出 5-10 条
- 验证压缩后旧 memory 标记为 compressed,新摘要插入
- 跨日触发逻辑:game_time 从 86400 跨到 86401,触发反思 + 压缩
- 真实 API 验证:跑一次林秋的反思,看输出质量

### Block I:对话状态机(Day 2 范围,但视觉冲击大)

**目标**:让两个 agent 真的开口说话,LLM 多轮生成对白,Godot 显示气泡/字幕。

**关键设计**(参见 v0.2 §1.5):
- 对话不走 Action Queue。一旦 agent A 触发 `talk_to(B)` → 双方 Action Queue 暂停 → 进入 `DialogueSession`
- 每句台词 2-4 秒"打字+显示"时间,期间 LLM 生成下一句
- 任意一方决定结束(达到 max_turn 或 leave_dialogue),双方退出对话状态、重启 Action Queue
- 对话内容写入双方 memory(memory_type='observation',importance 由发起方 LLM 评分)

**子任务**:
- backend:`DialogueSession` + scheduler 配合(暂停/恢复 Action Queue);WS 新事件类型 `dialogue_started` / `dialogue_line` / `dialogue_ended`
- Godot:对话气泡 / 字幕 UI;两个 agent 头顶冒泡或屏幕底部字幕(类似 GTA、巫师)

**预计工作量**:~2 小时(backend 1h + Godot 1h)。Block I 完成后视觉效果对比之前会有飞跃——agent 终于"会说话"了。
