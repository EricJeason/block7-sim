## 红线规则 — 看到 / 想动 这些请三思

| # | 红线 | 触碰前需要做什么 |
|---|---|---|
| 1 | **不引入向量检索 / embedding** | 不要做。设计文档明确决策。Memory 召回只能 SQLite LIKE + 时间衰减 |
| 2 | **不破坏 4 层 prompt 缓存的字节稳定性** | 改 LAYER_0_SYSTEM 或 build_rich_layer_1 → 必须重跑 `pytest tests/test_cache_hit_rate.py` 确认仍 ≥ 90%(¥1-3) |
| 3 | **scheduler.tick_agent / tick_all 不能阻塞或 await LLM** | 任何 LLM 调用必须走 asyncio.create_task,通过 _memory_write_tasks 集合追踪 |

| 6 | **不能 amend / force-push 已有 commit** | 项目协作规则;遇到要"修上一个 commit"的需求,创建新 commit |
| 7 | **不能 skip git hook (--no-verify)** | 同上 |
| 8 | **Pro think_high 调用必须 max_tokens ≥ 3000 + client timeout ≥ 90s** | 推理 token 也吃 max_tokens 配额。已是 deepseek.py 默认,但若新增其它 think_high 调用要记得 |

## 剩余 Block 详细规格

### Block G:每日反思 + Memory 压缩

**目标**:让长游戏(几十个游戏日)不爆 token + 提供可被 _plan_daily 消费的高层 reflection。

**两个独立子任务**:

#### G.1 每日反思(reflection.py 实现)
- 触发时机:每个游戏日结束时(由 Block H 的 sim loop 调度,或 scheduler 内部检测 game_time 跨日)
- 输入:当日所有 importance ≥ 4 的 memory(observation + plan)
- LLM:Pro + think_high(质量优先)
- 输出:5-10 条高层 reflection memory(如"今天三个治愈者都做了相似的梦,这不是巧合")
- 写入:memory_type='reflection',importance 由 LLM 给(自评分)
- prompt 模板放在 reflection.py,沿用 4 层结构(Layer 0 + Layer 1 + 当日 memory dump + reflection 任务)

#### G.2 旧 Memory 压缩(compression.py 完成)
- 触发时机:每个游戏日末尾(同 G.1)
- 规则(设计文档 §3.4):
  - 24 游戏小时内:全保留
  - 1-7 天前:importance ≥ 5 保留,importance < 5 合并为"日常摘要"(LLM 调用)
  - 7 天以前:仅保留 reflection 与 importance ≥ 7
- 实现细节:用 `MemoryStore.mark_compressed([ids])` 标记原始记忆;新摘要 memory 作为 reflection 类型新插入

**预计工作量**:~1.5 小时(LLMPlanner 已经为 prompt 构造打好基础,可复用 build_rich_layer_1)

**要测的**:
- mock 当日 50 条 memory → 验证 reflection 输出 5-10 条
- 验证压缩后旧 memory 标记为 compressed,新摘要插入
- 跨日触发逻辑:game_time 从 86400 跨到 86401,触发反思 + 压缩
- 真实 API 验证:跑一次林秋的反思,看输出质量

### Block H:FastAPI 路由 + WebSocket + Godot 联调

**目标**:Eric 能在 Godot 客户端里看见 12 个 agent 真实活动。

**子任务**:

#### H.1 FastAPI 路由(api/routes.py)
- `GET /agents`:列出所有 agent_id + display_name + current_location + current_action.action_type
- `GET /agent/{id}/state`:完整 AgentRuntime.snapshot()
- `GET /agent/{id}/memories?limit=20&type=observation`:按 type 取最近 N 条
- `POST /agent/{id}/inject_event`:玩家手动注入紧急事件(触发 emergency replan,用于 demo)
- `GET /world`:locations + agents 当前分布(给 Godot 初始化用)

#### H.2 WebSocket(api/websocket.py)
- `WS /ws/sim`:Godot 订阅 tick 事件
- 每个 tick(scheduler.tick_all 完成后)广播:
  - `agent_started_action` { agent_id, action_type, args, duration, started_at }
  - `agent_completed_action` { agent_id, action_type }
  - `agent_moved` { agent_id, from, to }(由 perception 副作用产生)
  - `dialogue_line`(预留,Block I 才会有)
- 心跳 + 断线自动清理订阅

#### H.3 Sim 调度器(整合 D + E + F + G 启动)
- 在 `main.py` lifespan 启动一个常驻 asyncio.Task,固定频率(如 1 真实秒 / tick)调 `scheduler.tick_all`
- 注入 LLMPlanner + PerceptionBroker + (G 之后) ReflectionRunner
- 注册全部 12 个 agent
- Game clock:1 真实秒 = 60 游戏秒(与 godot_client/scripts/game_clock.gd 一致)
- shutdown 时优雅停止

#### H.4 Godot 客户端
- AgentNode 接受 agent_id,从 WS 订阅事件,根据 action_type 播动画
- 4 张 location 背景图(可 ChatGPT/Imagen 生成 1280×720 占位)
- 12 个角色 sprite(粗略可即时生成)
- 简单 UI:左上角时间 + 当前选中 agent 的 inspector(显示 current_action / 最近 5 条 memory)

**预计工作量**:~3 小时(backend 1.5h + Godot 1.5h)。Godot 部分 Eric 可能需要更多手动操作(导入资产、设场景)

**要测的**:
- HTTP 路由单测(用 FastAPI TestClient)
- WebSocket 单测(订阅 + 收事件)
- 真实端到端:启动 backend → 打开 Godot → 看见 12 个 agent 至少有 1 个真实做了 action 并触发动画
